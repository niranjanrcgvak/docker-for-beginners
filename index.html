Why it breaks

Same code, different machine

Python version

Your laptop has 3.9, the server has 3.12. Syntax and libraries differ.

Missing library

Someone forgot to run pip install for one package.

Database version

PostgreSQL 13 here, 16 there. Queries behave differently.

Operating system

Windows paths and Linux paths. Different tools installed.

Definition

What is Docker?

Docker packages an application with everything it needs (code, runtime, libraries, settings) into a portable unit called a container.

Package

Describe the environment once in a Dockerfile.

Ship

Share the image through a registry, like Docker Hub.

Run

Start identical containers anywhere Docker is installed.

Four words to remember

The Docker vocabulary

Image

A read-only template. Like a Python class.

Container

A running instance of an image. Like an object.

Dockerfile

The recipe that builds an image. Like setup instructions in code.

Registry

Where images are stored. Docker Hub is like GitHub for images.

Block 2 · building images

A Dockerfile is a recipe

# 1. Start from a small official Python image

FROM python:3.12-slim

# 2. Work inside /app

WORKDIR /app

# 3. Copy requirements first, so installs are cached

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

# 4. Copy the rest of the code

COPY . .

# 5. Run as a normal user, then define the start command

RUN useradd --create-home appuser

USER appuser

EXPOSE 5000

CMD ["python", "app.py"]

Block 2 · building images

The seven instructions you need

InstructionMeaning
FROMBase image to start from
WORKDIRFolder inside the image where commands run
COPYCopy files from your machine into the image
RUNRun a command while building (install packages)
ENVSet an environment variable
EXPOSEDocument the port the app listens on
CMDDefault command when the container starts

Block 2 · building images

Layers and the build cache

Each instruction creates a layer. Docker reuses unchanged layers. Scenario: you edit app.py.

LayerResult on rebuild
FROM python:3.12-slimCached, instant
WORKDIR /appCached, instant
COPY requirements.txt .Cached, instant
RUN pip install …Cached, instant
COPY . .Rebuilt, your change is here
CMD …Rebuilt, a few milliseconds

Rule: put what changes least at the top.

Block 3 · state

Containers forget. Volumes remember.

Container filesystem

Temporary. Deleted together with the container.

Named volume

Managed by Docker. Best for database data. Survives container deletion.

Bind mount

A folder from your laptop. Best for live code editing, like our nginx exercise.

-v notes_data:/var/lib/postgresql/data

Block 3 · connecting containers

Ports and networks

Ports: laptop to container

-p 5000:5000 means host port : container port. This is how your browser reaches the app.

Networks: container to container

Containers in one Compose project find each other by service name.

DB_HOST=db

Watch out: inside a container, localhost means the container itself, not your laptop.

- "5000:5000"

depends_on:

ports lets your browser reach port 5000

environment tells the app where the database is: the service name db

depends_on waits until the database is healthy

The database service and volume

db:

environment:

POSTGRES_DB: notes

POSTGRES_USER: notes_user

POSTGRES_PASSWORD: notes_pass

volumes:

- notes_data:/var/lib/postgresql/data

test: ["CMD-SHELL", "pg_isready ..."]

volumes:

notes_data:

volumes keeps the data when the container is removed

healthcheck lets web wait until PostgreSQL is ready

When things go wrong

Common errors and fixes

SymptomFix
Cannot connect to the Docker daemonStart Docker Desktop and wait for it to say running
port is already allocatedChange the host port, for example 8081:80
Container exits immediatelyRun docker logs name and read the last lines
Connection refused to the databaseUse the service name db, not localhost
My code change does not showRebuild with docker compose up --build
no space left on deviceRemove old images; docker system prune, with care

Good habits

Six best practices

Small base images

Prefer slim or alpine variants where they work.

Pin versions

Use python:3.12-slim, not latest.

Use .dockerignore

Keep .git, venv and secrets out of images.

No secrets in images

Pass passwords at run time with env vars or secrets.

One job per container

Web and database are separate containers.

Run as non-root

Add USER in the Dockerfile.

Advice

How to keep learning

  1. Containerise your own project. Take any Flask or Node app you wrote and write its Dockerfile.
  2. Break things on purpose. Delete a volume, change a port, read the error.
  3. Read the logs first. Most problems explain themselves.
  4. Learn basic Linux. ls, cd, cat, grep, permissions. Containers are Linux.
  5. Use Git and Docker together. Dockerfile and Compose file belong in the repo.

Remember

Five things to take away

  1. An image is a template; a container is a running copy.
  2. A Dockerfile builds your image, put changing files last.
  3. Containers are disposable, use volumes for data.
  4. Containers reach each other by service name.
  5. Compose runs the whole app with one command.
